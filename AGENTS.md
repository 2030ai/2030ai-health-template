# Правила работы над проектом (AGENTS.md)

Файл читают все ИИ-агенты, работающие с этим vault: Claude Code, Cursor, ChatGPT Code Interpreter, любые другие. Здесь — **универсальные** правила. Специфика (конкретные интеграции, ключевые слова поиска в Gmail, имя Telegram-чата) — в `agent_docs/` или уточняется у пользователя.

## Описание проекта и целей пользователя

- Проект: персональная база знаний о здоровье на основе шаблона [2030ai/2030ai-health-template](https://github.com/2030ai/2030ai-health-template).
- Формат: Obsidian vault + git.
- Данные: markdown с YAML frontmatter. Оригиналы (PDF, фото, DICOM, экспорты) хранятся в `<ORIGINALS_DIR>` — **замените плейсхолдер на свой путь** (например, `~/Documents/health-originals/`, `~/Dropbox/health/` или `~/iCloud/health/`).
- Цель: накопление health-данных, выявление трендов, **информационный анализ** через ИИ — не медицинский совет.

## Назначение AGENTS.md и границы

- AGENTS.md содержит только универсальные правила, применимые ко всем задачам.
- Специфические инструкции хранить в профильных документах `agent_docs/` или уточнять у пользователя; не раздувать AGENTS.md.
- Все проектные документы хранить в `agent_docs/`, кроме `README.md`, `AGENTS.md` и `CLAUDE.md`.

## При начале работы над задачей

- Прочитать блок "Описание проекта и целей пользователя".
- Прочитать последние 10 записей `agent_docs/development-history.md`.
- По карте документов `agent_docs/index.md` открыть только релевантные файлы.
- При нехватке контекста задать вопросы пользователю.

## Источники данных

Стандартный набор (каждая строка — необязательный компонент, подключается при наличии у пользователя):

- `inbox/` — сырые файлы (PDF, фото, текст) для обработки.
- **Gmail** — письма от лабораторий и клиник. Канал: `google-mcp-readonly` (если установлен).
- **Telegram** — тематический чат пользователя с личными заметками о здоровье. Канал: `telegram-read` (если установлен). Имя чата указывает пользователь в `agent_docs/guides/health-update-workflow.md`.
- **Устройства** (Apple Health, Fitbit, Garmin, Oura, Whoop, Withings) — экспорты через приложение → `inbox/`.
- **Медицинские порталы** (Госуслуги / MyChart / ЕМИАС / Helsi / страховая) — ручное скачивание в `inbox/`.
- **Историческая миграция** (OneNote, Apple Notes, Notion, DayOne) — однократный импорт.

Полный каталог и инструкции по извлечению — `agent_docs/guides/data-sources.md`.

## Правила работы с данными

- Каждый файл в `data/` — один markdown с YAML frontmatter.
- Обязательные поля: `type`, `date`, `tags`, `source`, `status`.
- Провенанс (опционально, для не-manual): `origin_url`, `origin_type`, `origin_file`, `origin_date`.
- Если `source: manual` — поля провенанса **опускаются** (не оставлять пустыми).
- Оригиналы файлов → `<ORIGINALS_DIR>` (не в git).
- Wiki-links `[[полное-имя-файла]]` для связей между записями.
- Именование: `YYYY-MM-DD-<описание>.md`.

Полная спецификация — `agent_docs/guides/data-formats.md`.

## Анализ данных

- ИИ анализирует по запросу, без скриптов (кроме крайних случаев).
- Всегда добавлять дисклеймер: информационный анализ, не медицинский совет.
- Сравнивать с предыдущими значениями, искать тренды и корреляции.
- При обнаружении отклонений от нормы — явно предложить пользователю обсудить с врачом.

## Инструменты

- Для создания и редактирования файлов использовать штатные инструменты агента (Write/Edit в Claude Code, equivalent в Cursor). Не использовать Serena `create_text_file`/`replace_content`.
- Serena (если есть) — для символьной навигации по коду, не для записи файлов.
- Для внешних данных предпочитать read-only MCP (`google-mcp-readonly`, `telegram-read`), чтобы избежать случайной модификации источников.

## Универсальные правила

- Следовать существующим паттернам, правилам и соглашениям проекта.
- Документы держать краткими; вместо копирования кода/контента ссылаться на файлы.
- Если планируются большие изменения — сначала кратко согласовать подход с пользователем.
- Обновлять затронутую документацию.

## Приватность

- Репозиторий пользователя **должен быть приватным**.
- Никаких автоматических пушей, отправок данных, загрузок в облака, кроме явно разрешённых пользователем.
- Обезличивание (удаление ФИО, адресов, номеров полисов) — только по запросу пользователя.

## Чек-лист перед завершением задачи

- Проверить, что выполнены требования задачи.
- **Обязательно** добавить запись в `agent_docs/development-history.md` — что сделано, зачем, какие файлы затронуты. Формат и ротация описаны в начале файла. Субагенты тоже должны вносить записи.
- Если принято важное решение — добавить запись в `agent_docs/adr.md`.
- Свериться с `agent_docs/guides/dod.md`.
