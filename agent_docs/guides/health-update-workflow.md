# Workflow скилла `/health-update`

## Назначение

Единая точка входа для сбора и обработки health-данных из всех источников.

## Шаги выполнения

1. **Проверить `inbox/`** — Glob `inbox/*`, прочитать и распознать каждый файл (PDF, фото, текст).
2. **Поиск в Gmail** — `google-mcp-readonly: gmail_search` по ключевым словам (лаборатория, анализ, результат, клиника, имена локальных лабораторий пользователя).
3. **Чтение Telegram** — `telegram-read: message_ops` из тематического чата пользователя (имя чата указано ниже), новые сообщения с последнего запуска.
4. **Парсинг и классификация** — для каждой находки:
   - Определить тип данных (`blood-test`, `vital`, `doctor-visit` и т.д.).
   - Создать структурированный `.md` в соответствующей папке `data/<type>/`.
   - Переместить/сохранить оригинал в `<ORIGINALS_DIR>/<type>/`.
   - Проставить провенанс (`origin_url`, `origin_file` и т.д.).
   - **Удалить обработанный файл из `inbox/`** после подтверждения перемещения.
5. **Отчёт** — вывести сводку: что нового найдено, тренды, алерты.

## Пользовательская настройка

Замените плейсхолдеры на свои значения:

- `<ORIGINALS_DIR>` = путь к папке оригиналов (например, `~/Documents/health-originals/`).
- `<TG_CHAT>` = имя Telegram-чата с личными заметками о здоровье (например, «Я и здоровье»).
- `<GMAIL_QUERY>` = ключевые слова для Gmail-поиска. Базовый набор:
  - `"анализ OR результат OR лаборатория"`
  - `"клиника OR врач OR приём"`
  - `"<имена ваших локальных лабораторий>"` (например, `"labcorp OR quest"` или `"инвитро OR гемотест OR helix"`)

## Источники данных

| Источник | MCP / инструмент | Тип доступа |
|---|---|---|
| `inbox/` папка | Glob, Read | Локальный |
| Gmail | `google-mcp-readonly` | Read-only |
| Telegram `<TG_CHAT>` | `telegram-read` | Read-only |
| Apple Health | Shortcuts экспорт → `inbox/` | Ручной |
| Устройства носимой электроники | API-экспорт или app export → `inbox/` | Ручной |
| Медпорталы (Госуслуги / MyChart / Helsi / страховая) | Ручное скачивание → `inbox/` | Ручной |

Подробности по каждому источнику — в [`data-sources.md`](data-sources.md).

## Ограничения

- Gmail attachments: `google-mcp-readonly` не умеет attachment download — скачивайте вручную и кладите в `inbox/`, потом запускайте workflow.
- Telegram media в read-only контуре может не возвращать удобный абсолютный путь — используйте предварительно настроенный download_dir или ручное сохранение.
- Некоторые медпорталы защищают PDF водяными знаками — это нормально, сохраняйте как есть.

## Важно

- `data/devices/` хранит только сырые bulk-экспорты; после обработки данные раскладываются в `sleep/`, `activity/`, `vitals/` и т.д.
- Файлы из `inbox/` удаляются только после подтверждения успешного перемещения оригинала в `<ORIGINALS_DIR>`.
- При отклонениях от нормы — добавить в отчёт дисклеймер про консультацию с врачом.
