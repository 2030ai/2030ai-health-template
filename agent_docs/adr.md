# Architecture Decision Records

Файл хранит важные архитектурные решения и их обоснования. Новый ADR — в начало файла.

Формат:

```markdown
# [YYYY-MM-DD] ADR-NNN: Короткое название
## Статус
Принято | Предложено | Отменено | Заменено ADR-XXX
## Контекст
Что побудило решение.
## Решение
Что выбрали.
## Обоснование
Почему.
## Последствия
- (+) Плюсы
- (-) Минусы
## Альтернативы рассмотрены
- ...
```

# [2026-03-23] ADR-001: Obsidian vault как формат хранения
## Статус
Принято
## Контекст
Нужна система хранения персональных health-данных, совместимая с ручным редактированием, git и ИИ-анализом.
## Решение
Obsidian-совместимый markdown с YAML frontmatter. Каждая запись — отдельный `.md` файл.
## Обоснование
Obsidian даёт визуальный граф связей, Dataview-запросы, шаблоны. Markdown + YAML легко парсится ИИ. Git обеспечивает версионирование.
## Последствия
- (+) Человекочитаемые данные, нет vendor lock-in
- (+) ИИ отлично работает с YAML frontmatter
- (-) Нет валидации схемы на уровне инструмента
- (-) Большое количество файлов со временем
## Альтернативы рассмотрены
- JSON database (сложнее ручное редактирование)
- Daily notes (сложнее агрегация по типу данных)
- Single-file tables (конфликты git, медленный Obsidian)

# [2026-03-23] ADR-002: Оригиналы вне git, в локальной/iCloud-папке
## Статус
Принято
## Контекст
PDF анализов, фото, DICOM, raw-экспорты устройств — тяжёлые бинарные файлы, не подходят для git.
## Решение
Оригиналы хранятся в `<ORIGINALS_DIR>` (путь пользователя, по умолчанию `~/Documents/health-originals/`). В markdown-файлах — ссылка через `origin_file`.
## Обоснование
Git остаётся лёгким (только markdown). iCloud/Dropbox обеспечивают синхронизацию и бэкап.
## Последствия
- (+) Быстрый git clone, чистые диффы
- (+) Автосинхронизация между устройствами
- (-) Два места хранения — нужна дисциплина в провенансе
## Альтернативы рассмотрены
- Git LFS (усложняет setup, платный storage)
- Всё в git (раздувает репозиторий, приватность)
