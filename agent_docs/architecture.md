# Архитектура

## Обзор

Персональная база знаний о здоровье в формате Obsidian vault с git.

## Контекст

Пользователь собирает данные о здоровье из множества источников (лаборатории, врачи, устройства, наблюдения). Данные хранятся как markdown с YAML frontmatter. Анализ выполняется ИИ-агентом по запросу.

## Ключевые компоненты

- **Obsidian vault** (корень репозитория) — структурированные markdown-файлы в `data/`, шаблоны, dashboards.
- **Хранилище оригиналов** (`<ORIGINALS_DIR>`) — PDF, фото, экспорты. По умолчанию `~/Documents/health-originals/`; пользователь указывает свой путь (желательно с iCloud/Dropbox-синхронизацией для бэкапа между устройствами).
- **Скилл `/health-update`** — автоматический сбор данных из `inbox/`, Gmail, Telegram и других источников.
- **Анализ ИИ** — тренды, корреляции, рекомендации по запросу пользователя.

## Потоки данных

```
Источники (Gmail, Telegram, inbox/, устройства, медпорталы)
    → /health-update (парсинг, классификация)
    → data/*.md (структурированные данные)
    → <ORIGINALS_DIR>/ (оригиналы)
    → Анализ ИИ по запросу пользователя
```

## Технологии и зависимости

- Obsidian + плагины Dataview, Templates (Core).
- Git — версионирование.
- Claude Code (или другой ИИ-агент) + опциональные MCP: `google-mcp-readonly`, `telegram-read`.
- iCloud / Dropbox / локальный диск — синхронизация оригиналов.

## Нефункциональные требования и ограничения

- **Приватность**: репозиторий приватный, данные не отправляются вовне.
- **Без кода**: анализ только через диалог с ИИ, без Python-скриптов и серверов.
- **Медицинский дисклеймер**: всегда информационный анализ, не медицинский совет.
- **Минимум SaaS**: один агент + один редактор (Obsidian) + git. Никаких подписок.

## Roadmap (типичный)

1. Инициализация vault из шаблона.
2. Подключение 1–2 источников, первые записи.
3. Импорт исторических данных (OneNote/Apple Notes, Gmail за последний год).
4. Настройка дашбордов под свои приоритеты.
5. Итеративное расширение (новые источники, уточнение frontmatter, кастомные дашборды).
